# RFID 摄像头归档与照片回放设计

## 目标

将 RFID 信号监视器的一次检测保存为单个 `.ttp` 历史包。每一条 RFID 原始检测记录都关联当时最近的一帧摄像头画面；历史回放时，用户悬停曲线点可在照片面板查看相应图像。

## 范围与原则

- 每条 RFID 原始记录均写入历史表，即使多条记录命中同一摄像头帧。
- 同一摄像头帧仅编码、存储一次；表内多行可引用同一照片 ID，减小归档体积。
- 摄像头取流与 JPEG 编码不能阻塞串口读取或 Tk 主线程。
- 无摄像头、无可用画面或拍照异常时，RFID 检测与导出仍可完成，记录的照片 ID 为空。
- 原始检测、开始、停止和 RSSI 截取标签继续完整保留。

## 归档格式

`.ttp` 为 ZIP 容器，导出时先写入临时文件，成功完成后再原子改名。

```
rfid_history_YYYYMMDD_HHMMSS.ttp
├── history.csv
├── manifest.json
└── images/
    ├── frame_000001.jpg
    └── frame_000002.jpg
```

`history.csv` 使用 UTF-8 with BOM，列为：

| 列名 | 含义 |
| --- | --- |
| 到达时间 | 本机接收时间，毫秒精度 |
| 相对时间秒 | 本次检测开始后的秒数 |
| EPC | 完整 EPC |
| RSSI | 强度（dBm） |
| 标签 | 同一点多个标签用 `；` 合并 |
| 照片ID | 对应 `images/` 路径；无图像时留空 |

`manifest.json` 包含格式版本、导出时间、摄像头设置（设备、分辨率、JPEG 质量）及每个照片 ID 到归档内 JPEG 路径的映射。格式版本为 `1`。

## 摄像头采集

新增独立 `CameraWorker`：

1. 选择并开启摄像头后，后台线程持续读取画面。
2. 最新成功画面带单调递增帧 ID 与捕获时间。
3. RFID 事件由 UI 主线程处理时，读取最近画面引用；同一帧 ID 不重复保存。
4. 新帧按设置缩放（默认 640×480）并编码 JPEG（默认质量 55），存入本次运行的内存照片池。
5. 停止时将 CSV、清单与内存照片池统一打包为 `.ttp`。

同一摄像头帧可被多条 RFID 记录引用。若 RFID 频率高于摄像头帧率，记录仍逐条保存，只是照片 ID 会重复。

## 实时页面

在现有 RFID 连接设置中新增摄像头选择、启用拍照开关和 JPEG 质量设置。摄像头状态需说明“未启用 / 已连接 / 无画面 / 读取失败”。停止检测后不再导出单独 CSV，改为输出 `.ttp`；无 RFID 数据时不创建任何历史文件。

## 历史页面

历史记录页布局为“设置 : 曲线 : 照片 = 1 : 5 : 2”：

- 设置：选择 `.ttp`（兼容原先 CSV）、X 轴单位、EPC 多选筛选。
- 曲线：保持连续折线、水平滚动和滚轮缩放。每个原始点均绘制：带标签的点显示标签文字；无标签点以所属曲线同色的无文字小圆点显示。
- 照片：鼠标悬停曲线点时显示其 JPEG 和 EPC、到达时间、RSSI、标签。无图像时明确显示“该记录未关联照片”，不得保留前一点图片。

`.ttp` 打开时解压到专用临时目录。切换文件或关闭程序后清理该目录。损坏包、缺少 `history.csv`、不支持的版本或缺图均给出可理解错误；缺图不会阻止其余历史数据曲线显示。

## 模块边界

- `camera_worker.py`：摄像头枚举、后台取流、最新帧快照与错误状态。
- `history_io.py`：升级 `HistoryPoint`、`.ttp` 的导出/读取、旧 CSV 兼容。
- `history_view.py`：历史点筛选、视口与“最近点”悬停命中计算。
- `app.py`：摄像头控件、RFID-照片关联、曲线绘制、照片面板和临时目录生命周期。

## 验证

- 多条 RFID 记录引用同一帧时，CSV 记录完整而 JPEG 仅存一份。
- `.ttp` 读取可还原所有点、标签及照片映射；旧 CSV 可正常打开且显示无照片状态。
- 空检测不产生归档；无摄像头、摄像头断开和损坏 `.ttp` 均有可理解错误。
- EPC 过滤、缩放与横向滚动不改变照片对应关系。
- 串口主动和被动轮询现有行为、实时曲线与标记逻辑不回归。
