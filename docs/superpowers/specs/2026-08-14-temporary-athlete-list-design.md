# DetectOnly临时运动员名单设计

日期：2026-08-14

## 目标

在不恢复本地存储的前提下，为DetectOnly固件增加一场比赛内有效的临时运动员名单。APP在比赛进行中将已检测EPC定义为运动员或非运动员；固件维护运动员圈数、统一比赛时钟和8秒检测规则，并向APP返回运动员信息或普通EPC。

## 范围

保留开始、结束、查询状态、状态返回和通用执行状态。新增EPC定义、运动员名单查询和运动员信息返回。所有名单只存在于内存，成功结束比赛或设备重启后全部清除。

不恢复姓名、排名、领滑、本地文件、数据库、跨比赛数据和停止后的追圈业务。

APP保证不会出现重复定义、ID/EPC冲突、列表超容量、圈数溢出或总时长溢出。固件不为这些情况增加业务流程，只保证固定数组不会发生越界访问。

## 架构

采用集中式设计，扩展`DetectionController`统一维护比赛状态和三张固定表。`LoraManager`只负责协议收发，`RFIDReader`只负责RFID硬件通信和EPC队列，主程序负责模块之间的调用。

```text
RFIDReader
  → 原始EPC
DetectionController
  → 黑名单/运动员/普通EPC判断
  → 8秒判断、圈数和时间更新
SpeedSkatingTimer.ino
  → 调用LoraManager发送0x12、0x14或0xF0
```

## 内存数据

三张表容量均为50条，每个槽位包含`enabled`字段。查找、遍历、移除和复用均只依据该字段，不移动数组内容，不使用动态内存。

运动员记录包含：

```text
enabled
运动员ID
EPC
圈数
总时长（百分秒）
上次有效检测时间
是否已有有效检测时间
```

黑名单记录包含`enabled`和EPC。普通EPC临时记录包含`enabled`、EPC和上次有效检测时间。

控制器还维护检测状态、比赛开始时间、统一运动员时间偏移量，以及偏移量是否已经建立。

## 比赛生命周期

成功执行`0x01`时清空三张表和旧偏移量，启动比赛时钟。检测中重复执行`0x01`不改变任何状态。

成功执行`0x02`时停止检测并清空：

- 比赛时钟和统一偏移量；
- 50条临时运动员记录；
- 50条EPC黑名单记录；
- 50条普通EPC 8秒记录；
- 运动员自身的8秒记录；
- RFID接收队列。

停止状态重复执行`0x02`不进行操作。

## 运动员时间

比赛时钟从成功执行`0x01`开始。

定义第一名运动员时，将当前比赛时钟记录为统一偏移量，并将该运动员的初始圈数和总时长明确设为0。

定义后续运动员以及运动员有效过点时，运动员总时长均按以下公式计算：

```text
运动员总时长 = 当前比赛时钟 - 第一名运动员定义时的比赛时钟
```

所有运动员共用同一个偏移量，不建立个人计时起点。

## `0x10`定义EPC

`0x10`只允许在检测中执行，Payload固定为“是否为运动员1字节 + EPC 4字节 + 运动员ID 2字节”。定义为非运动员时忽略ID。

定义运动员：

1. 建立启用的运动员记录，圈数为0。
2. 第一名运动员建立偏移量且总时长为0；后续运动员使用统一偏移量计算初始总时长。
3. 将该EPC从普通EPC临时表中移除。
4. 先发送`0xF0`成功，再立即发送包含当前初始数据的`0x12`。

运动员建立时不继承该EPC作为普通EPC时的8秒记录，因此定义完成后第一次运动员检测可以立即生效。

定义非运动员：

1. 建立启用的黑名单记录。
2. 将该EPC从普通EPC临时表中移除。
3. 只发送`0xF0`成功。

## EPC处理

处理优先级固定为黑名单、运动员名单、普通EPC临时表。

黑名单命中后完全静默。运动员命中后使用运动员记录中的检测时间执行8秒判断；有效检测使圈数加一、总时长更新为当前比赛时钟减统一偏移量，并发送`0x12`。其他EPC使用普通EPC临时表执行8秒判断，有效检测发送只含EPC的`0x14`。

不足8秒的重复检测完全静默，不发送协议、不输出终端日志，也不更新上次有效检测时间。达到或超过8秒时允许再次检测。

## 名单传输

`0x11`只允许在检测中执行。有效请求按以下顺序同步发送：

```text
0x13开始
所有enabled运动员的0x12
0x13结束
```

空名单仍发送开始和结束。正常传输不发送成功`0xF0`。

## 协议

命令ID为：

```text
0x01 开始检测
0x02 结束检测
0x03 获取比赛状态
0x04 返回比赛状态
0x10 定义EPC
0x11 获取所有运动员信息
0x12 返回运动员信息
0x13 运动员传输状态
0x14 检测到普通EPC
0xF0 返回执行状态
```

`0x12`沿用运动员信息格式：运动员ID 2字节、圈数1字节、总时长3字节，所有多字节整数均为大端序，总时长单位为百分秒。

完整字段定义、状态码和示例以仓库根目录`LORAProtocol-byte.md`为准。

## 错误处理

协议长度、未知命令、校验和、包尾和状态不允许等错误继续通过`0xF0`返回，并在终端输出对应中文原因。8秒重复、黑名单命中属于正常静默路径，与`0xF0`无关。

## 测试要点

- `0x01`启动时钟，重复开始不重置数据。
- 第一名运动员初始圈数和总时长均为0，响应顺序为成功`0xF0`后跟`0x12`。
- 后续运动员的初始时间和有效过点时间均使用统一偏移量。
- 定义运动员或黑名单后，从普通EPC临时表移除对应EPC。
- 黑名单、运动员和普通EPC按固定优先级处理。
- 运动员和普通EPC分别执行8秒静默，互不共用检测时间。
- `0x11`对空名单和非空名单均形成完整的开始/结束序列。
- `0x02`清空全部启用标记、时钟、偏移量和接收队列。
- 三张固定表的遍历和复用不访问数组边界之外。
