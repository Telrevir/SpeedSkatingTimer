# 近10圈历史与名次查询设计

## 目标

DetectOnly固件在单场检测期间，为每名已定义运动员保存最近10次有效过线的圈数、当时名次和总用时。小程序发送既有`0x11`获取全部运动员成绩时，固件在当前成绩快照之外一并返回每名运动员的近10圈历史。

本设计替代未实现的“100圈分片重连同步”方案：不新增APP请求命令、不引入`0x16`或`0x17`，且不保存超过10圈的历史。



## 约束

所有数据仅保存在STM32运行期固定数组中；不使用动态内存、TF卡、Flash、EEPROM、数据库或ESP32专属接口。`0x02`结束检测、下一次`0x01`开始检测及`DetectionController::stop()`均清空近10圈历史。

现有实时`0x12`仍保持9字节格式，不增加名次字段。名次和16位圈数只在新的近10圈历史记录中返回，避免破坏当前实时小程序解析。



## 数据模型

每名`AthleteScoreEntry`保留已有当前成绩字段，并新增10项、每项7字节的环形字节数组：

```cpp
static constexpr uint8_t LAP_HISTORY_CAPACITY = 10;
static constexpr uint8_t LAP_HISTORY_RECORD_SIZE = 7;

uint8_t lapHistory[LAP_HISTORY_CAPACITY][LAP_HISTORY_RECORD_SIZE];
uint8_t lapHistoryCount;
uint8_t nextLapHistoryIndex;
```

每条记录统一采用大端序：

```text
byte0-byte1：圈数，uint16
byte2-byte3：名次，uint16
byte4-byte6：该次过线的总用时，uint24，单位为百分秒
```

首次通过`0x10`定义运动员不会写入历史。每次通过8秒静默规则的有效运动员过线，依次执行：更新当前圈数、单圈时长和总时长；计算该运动员的新名次；将圈数、名次和总用时写入`nextLapHistoryIndex`；递增并回绕该下标；最后发送既有`0x12`实时快照。

`lapHistoryCount`最大为10。第11条及之后的记录覆盖最早的一条。导出时从最早记录开始，按过线时间顺序读取至最新记录；调用方不得直接使用物理数组下标顺序。



## 名次规则

名次在每次有效运动员过线后计算，表示该运动员完成该圈之后的即时位置。比较规则固定为：

1. 圈数高的运动员靠前；
2. 圈数相同时，总用时短的运动员靠前；
3. 圈数和总用时都相同时，较早完成最近一次有效扫描的运动员靠前。

名次从1开始。尚无有效过线记录的运动员不会产生历史记录；其后首次有效过线时，按上述规则与其他已定义运动员一同参与比较。历史记录不因之后其他运动员的过线而回写，保留该条记录写入瞬间的名次。



## 协议

`0x11`仍由APP发起，Payload长度保持为0，且只允许在检测中执行。正常响应顺序调整为：

```text
0x13：开始传输
对每名已定义运动员依次发送：
  0x12：当前成绩快照，格式不变
  0x15：近10圈历史
0x13：结束传输
```

新增`0x15`“返回运动员近10圈历史”，仅由STM32发送：

```text
byte0-byte1：运动员ID，uint16
byte2：历史记录数，uint8，范围0～10
byte3...：按最早到最新顺序排列的7字节历史记录
```

Payload长度为`3 + 历史记录数 × 7`，范围3～73字节，低于当前230字节上限。即使运动员尚未完成有效过线，也必须发送记录数为0的`0x15`，确保小程序可区分空历史与漏包。

`0x12`在实时有效过线时仍单独发送；实时推送不附带`0x15`。小程序只有在发起`0x11`后的`0x13`开始和结束标记之间接收、缓存和替换近10圈历史。



## 模块边界

- `DetectionController.h`负责当前成绩更新、名次计算、7字节环形记录写入和按时间顺序只读访问。
- `DetectProtocol.h`负责`0x15`命令常量、7字节记录的大端写入以及Payload构建。
- `LoraManager.h`负责封装并发送`0x15`；不保存任何圈历史状态。
- `SpeedSkatingTimer.ino`负责在`0x11`批量传输中，对每名运动员依次发送`0x12`和`0x15`。
- `RFIDReader.h`和`RssiScoringController.h`不感知名次或历史存储；它们继续只提供过线事件及其计分时间。



## 失败处理

近10圈环形数组不产生容量错误；覆盖最早记录是正常行为。`0x15`发送失败时，使用既有`0xF0`返回原始命令`0x11`及LoRa发送失败状态，并仍尝试发送`0x13`结束标记，避免小程序停留在批量接收状态。

收到检测中以外的`0x11`、Payload长度错误、协议校验错误的处理维持现有行为。



## 验证

固件自测必须覆盖：

- 首次定义不写历史，首次和后续有效过线分别写入正确的大端字段；
- 圈数、总用时和扫描时间三层名次比较；
- 同一运动员连续11次有效过线后仅保留第2至第11条，且导出顺序正确；
- 多名运动员历史互不影响；
- 8秒内重复检测不新增记录；
- `0x02`及重新开始后历史为空；
- `0x15`的空历史、单条、10条Payload长度和字节内容；
- `0x11`传输顺序为`0x13开始 -> 0x12 -> 0x15 -> 0x13结束`。

小程序联调必须覆盖：空历史、完整10条历史、环形覆盖后的顺序、未知`0x15`前后兼容提示，以及50名运动员连续返回时的接收完整性。STM32实机联调应验证RSSI峰值模式下历史记录采用被选中的计分时间。
