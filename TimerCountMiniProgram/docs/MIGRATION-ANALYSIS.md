# Android 计时 APP 与微信小程序迁移分析

## 可行性结论

核心计时业务可以在微信小程序实现，但 Android 经典蓝牙 SPP 不能直接复用，必须通过 BLE GATT 通信；iOS 上也不能依赖小程序长期后台运行。因此，固件持续检测并保存当前运动员状态，小程序在恢复前台后用 `0x11` 重新获取成绩。

| 功能 | 可行性 | 当前实现 |
|---|---|---|
| BLE 连接与二进制协议 | 可实现 | BT04-E `FFE0/FFE2/FFE1`，增量解包和分片写入 |
| 开始、状态查询、停止重置 | 可实现 | `0x01`、`0x03/0x04`、`0x02` 及 `0xF0` 确认 |
| 运动员名单 | 可实现 | 微信本地保存、永久递增 ID、分组与归档 |
| EPC 分类 | 可实现 | `0x14` 后按本场范围串行发送 `0x10` |
| 圈数与总时间 | 可实现 | `0x12` 由固件提供权威值，小程序不再自行递增 |
| 单圈、排名、领滑、结束圈 | 可实现 | 小程序根据相邻总时间及圈数计算并固化 |
| 前台恢复 | 可实现 | 已连接时 `0x03/0x04`，Detecting 时执行 `0x11/0x13/0x12` |
| 任意后台持续接收 | 不保证 | iOS/微信生命周期限制，使用前台恢复同步补偿 |
| 云备份、多 EPC、扫描添加 | 后续能力 | 当前原型不实现 |

## 后续提醒

本地运动员数据和活动会话尚无云端容灾。若后续进入正式赛事使用，应优先增加云备份、恢复冲突策略和可观测日志；本原型按已确认要求未预留扫描添加或测试专用接口。
